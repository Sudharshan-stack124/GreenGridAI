## 1. Executive Summary

**GreenGrid** is an enterprise logistics decision-support platform engineered to help operations teams and race logistics coordinators evaluate shipping alternatives across delivery deadlines, transit times, financial expenditures, greenhouse gas (CO₂e) emissions, and real-time corridor disruptions.

This package contains the **User Dashboard frontend**, built with React, TypeScript, and Vite. It provides an operations command center for monitoring freight corridors, simulating real-world chokepoints and strikes, comparing candidate transport modes (Air, Road, Rail, Sea), and reviewing strategic AI decision explanations.

---

## 2. Key Architecture & Features

### 🌟 1. Control Dashboard
- **Telemetry & Status Bar:** Real-time visibility into 27 monitored shipments, 5 simulated disruptions, active corridor selection, and live vs. mock service modes.
- **Shipment Selection Panel:** Filterable by Formula 1 Championship calendar legs (23 races) and global commercial trade corridors (4 routes), featuring fuzzy search across ID, origin, destination, and cargo type.
- **Disruption Selection Panel:** Allows instant simulation of real-world bottlenecks:
  - `DIS-01`: Red Sea & Bab-el-Mandeb Maritime Security Closure (+13.5d, +$145k, +32% CO₂e)
  - `DIS-02`: North Atlantic Airspace Jetstream & ATC Strike (+2.5d, +$220k, +12% CO₂e)
  - `DIS-03`: Eurotunnel & Dover Channel Port Industrial Action (+2.0d, +$48k, +15% CO₂e)
  - `DIS-04`: Panama Canal Freshwater Draft Drought (+8.0d, +$95k, +18% CO₂e)
  - `DIS-05`: Typhoon Malakas East China Sea Port Operations Halt (+4.5d, +$60k, +8% CO₂e)
- **Shipment Specification Inspector:** Displays verified dataset fields: origin/destination facilities, GPS coordinates, cargo mass (tonnes & kg), allowed window (days), departure and deadline dates.
- **Recommended Transport Strategy Hero:** Prominently highlights the winning carrier mode, SLA deadline margin (+days), total cost breakdown, velocity, and carbon intensity.
- **Ranked Multimodal Alternatives Table:** Ranks Air, Road, Rail, and Sea with composite scores and feasibility reasons.
- **Strict Invariant Guarantee:** Never displays placeholder zeroes for infeasible routes. Infeasible modes explicitly display `N/A (Infeasible: Transoceanic barrier)` or `N/A (No rail corridor)`.
- **Multimodal Tradeoff Analytics:** Interactive comparison bars comparing Cost ($ USD), Transit Time (days vs. SLA limit line), and CO₂e emissions (tCO₂e) with carbon reduction highlights.
- **AI Decision-Support Explanation:** Detailed reasoning generated by the AI service (IBM Granite / watsonx.ai) detailing why specific modal shifts occurred.

### ⚡ 2. Disruption Matrix View (8 Benchmark Test Cases)
- Preconfigured test suite for all 8 official IBM Z Datathon test cases (`TC-01` through `TC-08`).
- One-click **"Load & Analyse Scenario"** action to stress-test Suez closures, Dover strikes, Transatlantic storms, and urgent cold-chain transports directly in the dashboard.

### 🗄 3. Frozen Benchmark Dataset Explorer (v2.1.1)
- Live tabular inspector for the 27 shipments and 5 disruptions from the frozen dataset, allowing auditability and validation of DEFRA emission factors.

## 4. Local Installation & Setup

### Prerequisites
- Node.js 18+ (Node 20 or Node 24 recommended)
- npm 9+ or pnpm

### Quick Start
```bash
# 1. Navigate to the frontend directory
cd frontend

# 2. Install dependencies
npm install

# 3. Configure environment variables (optional, defaults to mock mode)
cp .env.example .env

# 4. Start local development server
npm run dev
```

Open your browser at `http://localhost:5173`.

### Production Build & Preview
```bash
# Type check and build production bundle
npm run build

# Preview production build locally
npm run preview
```

## 5. API Integration & Service Architecture

The frontend is built with a decoupled service layer (`src/services/api.ts`) that normalizes both `camelCase` and `snake_case` payloads from Python/FastAPI microservices.

### Microservice Endpoints Supported
| Service | Config Variable | Default Local URL | Key Endpoints |
|---|---|---|---|
| **Data Service** | `VITE_DATA_SERVICE_URL` | `http://localhost:8001` | `GET /shipments`<br>`GET /shipments/{id}`<br>`GET /disruptions`<br>`GET /health` |
| **Decision Engine** | `VITE_DECISION_ENGINE_URL` | `http://localhost:8002` | `POST /recommend` |
| **AI Explanation** | `VITE_AI_SERVICE_URL` | `http://localhost:8003` | `POST /explain` |

### Environment Variables (`.env`)
```bash
# Set backend service URLs
VITE_DATA_SERVICE_URL=http://localhost:8001
VITE_DECISION_ENGINE_URL=http://localhost:8002
VITE_AI_SERVICE_URL=http://localhost:8003

# Set to 'false' to connect to live services; 'true' to use verified mock dataset
VITE_USE_MOCKS=true
```

You can also switch between Mock Mode and Live API directly from the toggle in the dashboard header without restarting Vite.
